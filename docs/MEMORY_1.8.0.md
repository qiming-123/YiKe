# 1.8.0 内存与质量测量

Windows 本机约15.38GiB物理内存，20逻辑处理器。输入仅为固定合成句子，不使用个人文档。峰值为对应子进程的工作集/私有内存，不含 WPF、系统文件缓存及其他进程。

| 配置 | 工作集峰值 | 私有内存峰值 |
| --- | ---: | ---: |
| 原 Qwen0.6B，4096上下文、128/64批量 | 1166MiB | 885MiB |
| 调整 Qwen0.6B，3072上下文、64/32批量 | 1052MiB | 771MiB |
| OPUS-MT INT8，CTranslate2 4.8.4，2线程、CT2_PACKED_GEMM=0 | 129MiB | 150MiB |

原始测量文件由 artifacts/memory-before.json、memory-after.json、nmt-final-low-memory.json 归档到本目录。通用模型门槛测试使用受控硬件快照；没有通过占满机器内存完成“真实只剩1–2GiB”的压力实验，不能保证所有系统负载下都能启动。

专用模型在本次“直到下载结束之前不要关闭”“仅在配置有效时重启”样例中保留了否定与条件关系；Qwen0.6B 同类样例曾丢失语义，提示词调整未能可靠解决，因此增加专用引擎。专用模型也有错误：square 在扫雷上下文中可能译为“广场”，unmarking 的措辞不自然。没有大规模标准基准，不给出整体准确率提高百分比。

测量中的31–62ms是模型已加载后的单句解码时间，不是冷启动、完整划词或UI响应时间。生产按次启动释放内存，会增加冷启动耗时，避免后台长期占用。现阶段优先满足低内存可用性。
