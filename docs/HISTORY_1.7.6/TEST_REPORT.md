# 译刻 1.7.6 · 未选中文字误弹窗修复验收

2026-10-25（America/Denver，客户端日期）。本轮纠正 1.7.5 未确认选区便显示读取卡片、读取失败后留下错误的问题。此前响应优化资料保留在 HISTORY_1.7.5。

## 修复行为

自动鼠标流程只将手势视为候选。必须从目标程序读取到非空的实际文字选区，才创建翻译浮窗并提交翻译。确认超长的选区仍提示限制。NoSelection、NotTextSelection、Unsupported、Timeout、AccessDenied 和 TargetGone 都保持安静，仅在设置诊断中记录状态；不因为尝试取词失败就弹卡。

已移除自动读取阶段的计时浮窗、未读取提示 API 和当前视觉夹具。真正选区确认后仍立即显示加载 / 翻译进度；第一段有效译文继续立即发布，同文复用、辅助进程预热、最长 2.2 秒有界重查保留。明确点击“粘贴文本翻译”或 VS Code 终端快捷键是显式操作，仍显示必要失败信息。

在尝试读取焦点文档之前，检查起点控件的有界祖先链。按钮、复选框、单选框、菜单、工具栏、标签、组合框、表头和滑块等操作区域终止，不借用旧焦点选区。嵌在工具栏或组合框内的 Edit 以及普通 Document / 文本列表仍可继续读取真实选区。文件和桌面过滤保留。

拖动阈值由固定 4 个物理像素改为按窗口 DPI 缩放的 6 DIP，减少点击时抖动。双击按两次按下时间计算，修复第一次长按很久后，下一次普通单击因两次松开时间接近而误算双击。极短单字的拖动可能达不到阈值，可通过双击选择；没有确认文字时不提交模型请求。

## 检查范围与限制

本轮主要通过手势、控件路径、自动呈现策略、生产协调器、真实本地模型及自有 WPF 控件验证。没有在用户真实浏览器、WPS、VS Code 等每一种应用中实点空白处或拖选，不声称已覆盖所有应用的访问接口。目标程序可能没有提供可读取选区；此时自动操作现在安静记录，可手动粘贴翻译。

保留的热机响应检查不包括鼠标与 UIA 读取，其样例关闭了专业说明以测纯翻译，不能作为所有文本的延迟保证。轻量模型两条扫雷句子的 2 项内容失败仍在 WORD_LIVE_LIGHT.json 中，没有视为语义通过；说明模型的格式通过不保证知识正确。

完整离线安装的隔离检查覆盖不装模型、无效参数、两档模型及双模型、损坏修复、散列复用、偏好保留、真实推理、卸载器签名与正式用户状态不变。没有关闭网络或安全设置，也未在另一台全新 Windows 上完成 GUI 安装。
